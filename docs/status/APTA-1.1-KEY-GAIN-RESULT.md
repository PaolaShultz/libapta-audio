# Synthetic input-gain diagnostic — completed, documented 2026-09-10

The [protocol](APTA-1.1-KEY-GAIN-PROTOCOL.md) and the eight fixed gain runs date
from 2026-09-05. On resumption 2026-09-10, every retained report/replay hash was
verified and the complete summary regenerated byte-identically without rerunning
PCM or adding gain levels. Source baseline is
`1e3a151ed625b82c276b5117c498dfe64f301dd7`; the diagnostic instrumentation was
uncommitted during execution. This is synthetic diagnostic evidence, not an
accepted detector or a clean release qualification.

## Result

Changing only the amplitude changes final native tonic/mode decisions. All
13,824,000 input samples per run recover exactly after inverse binary gain,
stay within [-1,1] without clipping, and retain the same signal/noise ratio.
All 288 raw-energy windows per run scale exactly by gain squared; raw-folded
argmax remains unchanged. Thus the observed changes do not require different
musical content or a gain-dependent raw-extraction decision on these stimuli.

| Input gain | Default clean major /12 | Band clean major /12 | Default clean minor /12 | Band clean minor /12 |
|---|---:|---:|---:|---:|
| 1/16 | 12 | 11 | 12 | 12 |
| 1/4 | 9 | 2 | 12 | 12 |
| 1 | 4 | 0 | 11 | 12 |
| 2 | 2 | 0 | 11 | 10 |

These are four-window matches to the fixed synthetic progression identity.
They are not real-song accuracy measurements. Individual IV/V window outputs
are retained as diagnostics and are not scored as global-key errors.

Relative to gain 1, the complete 72-progression set (clean, detuned and noisy;
both modes) changes as follows:

| Gain | Default changed final /72 | Of these mode only | Band changed final /72 | Of these mode only |
|---|---:|---:|---:|---:|
| 1/16 | 32 | 18 | 34 | 26 |
| 1/4 | 21 | 10 | 8 | 3 |
| 1 | 0 | 0 | 0 | 0 |
| 2 | 11 | 6 | 3 | 0 |

The remainder of the changed cases has a tonic change, possibly together with
mode. On clean major progressions, mean final min/mean chroma rises from
0.1024 to 0.6562 across the four gains in default and from 0.2957 to 0.7968 in
band. Default mean best-major minus best-minor margin changes from +0.01771
to -0.01155; band changes from +0.01312 to -0.01690. These are group means,
not a statement that every individual item changes monotonically.

The current absolute-energy compression/folding/scoring path is therefore
gain-sensitive on the frozen synthetic inputs. This is stronger evidence for
a scale-normalization hypothesis, but does not establish a preferred gain,
a replacement compression curve, or the cause of every real-song error.
No production behavior or confidence mapping was changed.

## Implementation and verification

`apta_key_gain_diagnostic` is an explicit-build-only target. It uses the
existing contrast observer and accepts only `--json --gain-shift` followed by
one of `-4`, `-2`, `0`, `1`. The default contrast/mode/reference executables
keep their existing invocation and behavior. The generator scales the already
rounded float mixture with `ldexpf`; no new detector option is introduced.

The fixed run and validation matrix passed:

- default and band Release/Werror builds;
- all eight registered gain runs and byte-identical repeats;
- band ASan/UBSan at all four gains, each byte-identical to band Release;
- six invalid CLI cases per build (18 in total), rejected before PCM output;
- six summary tests, covering binary-energy scaling, corruption, invalid gain,
  incomplete input, baseline-hash rejection and change-count denominators;
- gain-1 identity with all 720 original contrast rows in each build and
  identical ideal-vector rows at every gain;
- exact raw-energy scaling, unchanged raw-folded argmax and bit-identical
  observer reconstruction after all 288 windows per run;
- unchanged default/band production analyzer and native key object hashes,
  including re-verification on 2026-09-10.

The gain counters occupy 16 test-process bytes (4 + 4 + 8, verified in the
native symbol table). Existing observer scratch is 476 bytes default / 1,124
bytes band; session sizes remain 11,824 / 12,784 bytes. Native runtime/state
delta is zero because neither diagnostic macro is enabled in the core. No
full native matrix or P4 qualification was rerun for this test-only change.

The gain-1 baselines contain no high-confidence final outputs. Gain 1/16
produces twelve such outputs in default and two in band, with zero mismatches
to these synthetic stimulus identities; the other fixed gains produce none.
This is a confidence observation, not corpus safety evidence or calibration.

## Decision and next step

The gain hypothesis is retained and this diagnostic task is complete. The next
work is to preregister one bounded, scale-invariant per-window energy
normalization before compression, with an explicit silence rule, fixed
aggregation/profile/confidence behavior, resource limit and no-regression veto.
Require gain invariance and preserved minor behavior on synthetic checks before
any independent development comparison. Do not select the lowest gain as an
input workaround or tune normalization constants against these results.
Any real candidate remains opt-in and requires independent transfer and safety
evidence; no FMAK relabeling, corpus access, holdout or release gate was used.

That follow-up is now complete: the
[mean-normalization candidate](APTA-1.1-KEY-MEAN-NORMALIZATION-RESULT.md)
passes its synthetic gates but is rejected on CPU/stack cost. Its result
document records the current continuation boundary; this gain diagnostic's
evidence and interpretation remain unchanged.
